# Development

## Environment

Any Linux/macOS machine with Python 3.10+ works for development; nothing except
the final on-device run needs the CardputerZero.

```bash
python3 -m pip install --user pillow pytest ruff
# optional, only for rendering the mockups with the exact DejaVu faces
python3 -m pip install --user matplotlib
```

`python3-dbus` and `python3-gi` are only imported by the Bluetooth transport;
the tests never touch them.

## Layout

```
src/mouse_jiggler/
├── app.py            state machine, timers, keys, render dispatch
├── state.py          State enum
├── config.py         persisted JSON (mode, last host)
├── modes.py          the three modes, shared by UI and motion
├── hid/
│   ├── descriptor.py 64-byte report descriptor, REPORT_ID = 2
│   ├── reports.py    4-byte report encoding + HIDP header
│   └── motion.py     vectors, periods, drift-free alternation
├── bt/
│   ├── sdp.py        SDP record (descriptor injected)
│   ├── profile.py    BlueZ D-Bus: profile, adapter, pairing props
│   ├── agent.py      Agent1 auto-accept + GLib loop
│   ├── server.py     L2CAP listeners, HIDP control, report fanout
│   └── transport.py  facade used by the app
├── platform/fb.py    framebuffer discovery, ioctl/mmap, RGB565
├── input/keypad.py   raw evdev reader
└── ui/
    ├── theme.py      palette + geometry tokens
    ├── fonts.py      DejaVu 10/12/16 loading
    ├── icons.py      vector icons at 4x supersampling
    ├── screens.py    home / pairing / confirm / rename / error
    └── icon.py       launcher icon
```

Data flow: `App.step()` polls the keypad, polls the transport, reconciles the
connection, fires due motion ticks, then redraws if needed. Motion never sleeps;
the app owns the schedule (`next_tick`, absolute `time.monotonic()` deadlines
with a catch-up guard).

## Tests

```bash
python3 -m pytest tests -q
python3 -m pytest tests/test_app.py -q          # state machine only
python3 -m pytest tests/test_hidp.py -q         # protocol + socketpair session
ruff check src tests tools
```

The suite needs no hardware. The fakes live in `tests/support.py`:
`FakeClock`, `FakeTransport`, `FakeDisplay`, `ScriptedKeypad`. A typical test:

```python
def test_feature(env):
    app, transport, display, keypad, clock, config = env
    transport.connect()
    app.step()                       # OFFLINE -> CONNECTED
    press(app, KEY_ENTER)            # Start
    clock.advance(30)
    app.step()
    assert transport.reports == [(2, 0)]
```

Rules:

- Never `time.sleep` or read the wall clock in a test; advance `FakeClock`.
- Assert on `app.state`, `transport.reports`, `config`, and rendered image size —
  not on private drawing details.
- `HidClient` is exercised over `socket.socketpair(AF_UNIX, SOCK_SEQPACKET)`, so
  the HIDP framing is tested without a Bluetooth adapter.

## Preview the UI

```bash
python3 tools/render_assets.py
```

Writes `docs/ui-mockup.png`, `ui-running.png`, `ui-mode.png`, `ui-rename*.png`,
`ui-pairing.png` and `assets/icon-256.png`. The images are generated by the same
`screens.render_*` functions the device uses, so a visual diff is a real
regression signal. Commit them when the UI changes intentionally.

To render an arbitrary state:

```python
import sys; sys.path.insert(0, "src")
from mouse_jiggler.ui import screens
screens.render_home(screens.HomeState(selected=2, running=True, mode=2)).save("/tmp/mode.png")
```

## Adding or changing a screen

1. Add a `render_*` function in `ui/screens.py` using `_canvas()`, `_header()`,
   `_footer()` and the tokens in `ui/theme.py`.
2. Add a `State` value in `state.py` and a branch in `App.render()`.
3. Add a test in `tests/test_ui.py` (size, background, accent pixel).
4. Regenerate the assets.

Keep to the 320×170 grid and the 1 px border convention (outer rect in the
border color, inset fill at `+1 px`), otherwise the look diverges from the
reference app.

## Changing a mode

Edit `modes.py` (period, subtitle, step). Then:

- `hid/motion.py` uses `period`, `step`, `jiggle_min/max`.
- The UI subtitle comes from the same `Mode.subtitle`.
- Update the table in `README.md`, `docs/usage.md`, `PLAN.md`, and the timing
  test in `tests/test_motion.py`.

## Bluetooth work

The protocol reference is [protocol.md](protocol.md). On hardware, start with
the M0 spike before touching the app:

```bash
sudo python3 - <<'PY'
# see docs/protocol.md §9 for the full spike
PY
bluetoothctl show
bluetoothctl devices
journalctl -u bluetooth -n 80
```

The app-level transport is deliberately dumb: `transport.poll()` accepts sockets
and answers HIDP control frames; `send_mouse()` writes `A1 02 …` on the
interrupt channel. If pairing behaviour needs to change, it is in
`bt/profile.py` (`set_pairing`, `register_profile`) and `bt/agent.py`.

## Packaging

```bash
APP_ROOT=/tmp/czroot SKIP_RESTART=1 ./install.sh install   # stage layout
./packaging/build-deb.sh 0.2.2                            # dist/*.deb

# same thing without a Debian host: build inside a container
docker run --rm --user "$(id -u):$(id -g)" -v "$PWD:/src" -w /src \
  ubuntu:24.04 ./packaging/build-deb.sh
```

`build-deb.sh` calls `install.sh` with `SKIP_DEPS=1` (staging does not need
Pillow/dbus) and `SKIP_RESTART=1` (never touch services during a build).

`install.sh` skips `sudo` when the target tree is writable, which is what makes
staging and CI possible. `build-deb.sh` reuses the same script with
`APP_ROOT=<stage>/usr/share/APPLaunch`.

## Style

`ruff check` with the config in `pyproject.toml` (line length 100, import
sorting, pyupgrade, bugbear). Type hints are used throughout but `mypy` is not
configured; keep public functions annotated.
